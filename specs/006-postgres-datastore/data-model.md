# Phase 1 Data Model: Durable Multi-Writer Metadata Store

**Feature**: `006-postgres-datastore` · **Date**: 2026-07-30 · **Research**: [research.md](./research.md)

**This feature introduces no new entities and changes no entity's meaning** (spec, Key
Entities). Every table below already exists in `app/db.py`'s `SCHEMA`. What changes is the
engine underneath, the type spellings, and — for three constraints — whether the guarantee
is real under concurrency or was only ever held up by a global write lock.

The store **starts empty** (FR-004). There is no migration of data, so there is exactly one
migration file: the whole schema at version `0001`.

---

## Type mapping

Applied uniformly. The rationale for the two conservative choices is in research R5 and R6 —
both protect FR-001 (no user-facing change) and SC-007 (identical before/after walkthrough).

| SQLite | PostgreSQL | Notes |
|---|---|---|
| `TEXT` (identifiers, names, states) | `text` | No length limits; the app validates lengths (`models.py`) |
| `TEXT` (ISO-8601 timestamps) | `text` | **Deliberate** — see R5. Lexicographic order is chronological for ISO-8601 UTC |
| `INTEGER` (0/1 flags) | `smallint` | **Deliberate** — see R6. App writes `int(...)`, reads `bool(...)` |
| `INTEGER` (RGL/season ids) | `integer` | Externally-assigned ids from RGL |
| `INTEGER PRIMARY KEY AUTOINCREMENT` | `integer GENERATED BY DEFAULT AS IDENTITY` | `BY DEFAULT`, not `ALWAYS` — tests insert explicit ids (R7) |
| `INTEGER` (counts, slots, deltas) | `integer` | |
| `PRAGMA foreign_keys = ON` | *(nothing)* | Always enforced; cannot be forgotten (R12) |

**`steam_id` stays `text`, everywhere.** A SteamID64 exceeds 32 bits and is treated as an
opaque identifier throughout the app — never arithmetic, always compared and stored whole.

## Schema

`migrations/0001_initial.sql`, applied by the runner in
[contracts/store-access.md](./contracts/store-access.md).

### Migration bookkeeping

```sql
CREATE TABLE IF NOT EXISTS schema_migrations (
    version     text PRIMARY KEY,
    applied_at  timestamptz NOT NULL DEFAULT now()
);
```

The one place a real timestamp type is used, because nothing in the app reads it — it exists
for the operator and the runner.

### Accounts and league identity

```sql
CREATE TABLE users (
    steam_id       text PRIMARY KEY,
    persona_name   text,
    avatar_url     text,
    created_at     text NOT NULL,
    last_login_at  text NOT NULL
);

CREATE TABLE rgl_links (
    steam_id           text PRIMARY KEY REFERENCES users(steam_id),
    profile_name       text,
    state              text NOT NULL,
    is_verified        smallint NOT NULL DEFAULT 0,
    is_banned          smallint NOT NULL DEFAULT 0,
    is_on_probation    smallint NOT NULL DEFAULT 0,
    linked_at          text NOT NULL,
    last_refreshed_at  text NOT NULL
);

CREATE TABLE rgl_teams (
    rgl_team_id    integer PRIMARY KEY,
    name           text NOT NULL,
    tag            text,
    format         text NOT NULL,
    division_name  text,
    season_id      integer,
    updated_at     text NOT NULL
);

CREATE TABLE rgl_memberships (
    steam_id     text NOT NULL REFERENCES users(steam_id),
    rgl_team_id  integer NOT NULL REFERENCES rgl_teams(rgl_team_id),
    PRIMARY KEY (steam_id, rgl_team_id)
);
```

`rgl_teams.rgl_team_id` is **not** an identity column — RGL assigns it. Same for
`rgl_seasons.season_id`.

### Cached league data

```sql
CREATE TABLE rgl_rosters (
    rgl_team_id  integer NOT NULL REFERENCES rgl_teams(rgl_team_id),
    steam_id     text NOT NULL,
    name         text NOT NULL,
    is_leader    smallint NOT NULL DEFAULT 0,
    PRIMARY KEY (rgl_team_id, steam_id)
);

CREATE TABLE rgl_roster_meta (
    rgl_team_id  integer PRIMARY KEY REFERENCES rgl_teams(rgl_team_id),
    fetched_at   text NOT NULL
);

CREATE TABLE rgl_seasons (
    season_id         integer PRIMARY KEY,
    name              text NOT NULL,
    format            text,
    division_sorting  text NOT NULL DEFAULT '{}',
    fetched_at        text NOT NULL
);

CREATE TABLE rgl_season_teams (
    season_id    integer NOT NULL REFERENCES rgl_seasons(season_id),
    rgl_team_id  integer,
    division_id  integer,
    hydrated_at  text,
    PRIMARY KEY (season_id, rgl_team_id)
);
```

**Two deliberately absent foreign keys, preserved exactly as they are today:**

- `rgl_rosters.steam_id` has no `REFERENCES users` — a roster lists RGL players, most of whom
  have never signed in here. An FK would make caching a roster fail.
- `rgl_season_teams.rgl_team_id` has no `REFERENCES rgl_teams` — the division browser records
  which teams are registered in a season *before* hydrating their details, and hydration is
  bounded per request (`RGL_HYDRATE_BATCH`). An FK would forbid the very state that makes the
  browser bounded.

Adding either would look like tightening integrity and would in fact break FR-001 behavior.
`rgl_team_id` stays `NOT NULL` by virtue of being in the primary key.

**This is also what makes the cold-cache edge case survivable** (spec Edge Cases, FR-007):
starting empty discards the directory, and the first browse repopulates it through the same
bounded hydration path, with no FK standing in the way.

### Scrims

```sql
CREATE TABLE scrims (
    id                integer GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    format            text NOT NULL,
    scheduled_at      text NOT NULL,
    origin            text NOT NULL,
    proposer_team_id  integer NOT NULL REFERENCES rgl_teams(rgl_team_id),
    opponent_team_id  integer REFERENCES rgl_teams(rgl_team_id),
    status            text NOT NULL,
    created_by        text NOT NULL REFERENCES users(steam_id),
    created_at        text NOT NULL,
    updated_at        text NOT NULL,
    notes             text
);

CREATE TABLE scrim_attendance (
    scrim_id         integer NOT NULL REFERENCES scrims(id),
    player_steam_id  text NOT NULL,
    player_name      text NOT NULL,
    status           text NOT NULL,
    marked_by        text NOT NULL REFERENCES users(steam_id),
    updated_at       text NOT NULL,
    PRIMARY KEY (scrim_id, player_steam_id)
);
```

`scrim_attendance.player_steam_id` has no FK for the same reason as `rgl_rosters.steam_id` —
attendance is marked for roster players, not only for platform accounts. `marked_by` does
have one: whoever marked it necessarily signed in.

### Payment, credits, servers

```sql
CREATE TABLE steam_trade_links (
    steam_id      text PRIMARY KEY REFERENCES users(steam_id),
    trade_url     text NOT NULL,
    partner_id    text NOT NULL,
    access_token  text NOT NULL,
    updated_at    text NOT NULL
);

CREATE TABLE payments (
    id               integer GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    steam_id         text NOT NULL REFERENCES users(steam_id),
    method           text NOT NULL,
    provider_ref     text,
    state            text NOT NULL,
    state_reason     text,
    items_expected   integer NOT NULL,
    items_received   integer,
    credits_granted  integer,
    hold_until       text,
    target_scrim_id  integer REFERENCES scrims(id),
    created_at       text NOT NULL,
    updated_at       text NOT NULL,
    UNIQUE (method, provider_ref)
);

CREATE TABLE servers (
    id                integer GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    scrim_id          integer REFERENCES scrims(id),
    owner_steam_id    text NOT NULL REFERENCES users(steam_id),
    team_id           integer REFERENCES rgl_teams(rgl_team_id),
    state             text NOT NULL,
    name              text NOT NULL,
    map               text NOT NULL,
    max_slots         integer NOT NULL,
    join_password     text,
    address           text,
    players           integer,
    window_starts_at  text,
    window_ends_at    text,
    term_ends_at      text,
    grace_used        smallint NOT NULL DEFAULT 0,
    demo              smallint NOT NULL DEFAULT 0,
    stopped_reason    text,
    created_at        text NOT NULL,
    updated_at        text NOT NULL
);

CREATE UNIQUE INDEX idx_servers_scrim ON servers(scrim_id)
    WHERE scrim_id IS NOT NULL;

CREATE TABLE credit_ledger (
    id          integer GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    steam_id    text NOT NULL REFERENCES users(steam_id),
    delta       integer NOT NULL,
    kind        text NOT NULL,
    cause       text NOT NULL,
    payment_id  integer REFERENCES payments(id),
    scrim_id    integer REFERENCES scrims(id),
    server_id   integer REFERENCES servers(id),
    created_at  text NOT NULL
);

CREATE INDEX idx_credit_ledger_steam_id ON credit_ledger(steam_id);
```

**`servers` carries no administrative password column, and must not gain one.** Constitution
IV: the RCON password must never be stored beside a server's joinable details nor reach a
client. The absence is load-bearing, and it survives the engine change unexamined only if
somebody says so — so this says so.

**`credit_ledger` is append-only.** No `UPDATE`, no `DELETE`, ever. Balances are `SUM(delta)`
(FR-013). The `idx_credit_ledger_steam_id` index is what keeps that sum cheap as the ledger
grows, and it is now also the index the per-account row lock (R9) rides alongside.

## Constraints, and which requirement each one carries

The point of moving engines is that these stop being aspirations.

| Constraint | Requirement | Was it real before? |
|---|---|---|
| `UNIQUE (method, provider_ref)` on `payments` | **FR-009** — a payment grants credits exactly once | Yes — and it stays the guarantee, unchanged |
| `idx_servers_scrim` partial unique index | **FR-010** — at most one server per scrim | Real, but only ever tested against one writer |
| Every `REFERENCES` clause | **FR-011** — no orphan ledger entry, attendance mark, or server | **Only since 005**, and only because a per-connection pragma was remembered. Now unconditional |
| Row lock in `credits._spend` (R9) | **FR-012, FR-013** — a balance cannot go negative | **No.** Held up by SQLite's global write lock; must be built |
| Single transaction in `attach_to_scrim` (R19) | **FR-012** — reservation and server commit together | **No.** Two transactions today; must be fixed |
| `ON CONFLICT` in `upsert_on_login` (R19) | **FR-014** — two app copies, concurrent first sign-in | **No.** Read-then-write today; must be fixed |
| `schema_migrations` + advisory lock (R13) | **FR-015, FR-019** — ordered, once, safe when copies race | **No.** `executescript` on every startup; must be built |

The three "No" rows are the actual engineering in this data model. Everything above them is
a transcription.

## Identity sequences

`GENERATED BY DEFAULT AS IDENTITY` permits explicit ids, which existing tests use. An
explicit insert does **not** advance the sequence, so a later auto-generated insert can
collide (research R7).

Two rules, both enforced by the test harness rather than by discipline:

1. `TRUNCATE … RESTART IDENTITY CASCADE` between tests resets every sequence, so a collision
   cannot outlive one test.
2. A test that inserts an explicit id and then relies on auto-generation in the same test must
   do one or the other. There are few; auditing them is a task.

Application code never inserts an explicit id into an identity column, and must not start.

## Entity relationships

Unchanged from feature 005 — reproduced because the schema must account for every one.

```text
users ─┬─< rgl_links                (1:0..1)
       ├─< rgl_memberships >─ rgl_teams
       ├─< steam_trade_links        (1:0..1, secret-bearing)
       ├─< payments ────────────┐
       ├─< credit_ledger >──────┤   (payment_id, scrim_id, server_id all nullable)
       ├─< scrims (created_by)  │
       └─< servers (owner)      │
                                │
rgl_teams ─┬─< rgl_rosters      │   (roster steam_ids are NOT accounts)
           ├─< rgl_roster_meta  │
           ├─< scrims (proposer, opponent)
           └─< servers (team)   │
                                │
rgl_seasons ─< rgl_season_teams │   (rgl_team_id deliberately unconstrained)
                                │
scrims ─┬─< scrim_attendance    │
        ├─< servers             │   (at most one, by partial unique index)
        └─< payments (target) ──┘
```

**`users` is the root.** Which is why it is also the right row to lock for a per-account
credit spend (R9): every ledger entry has one, and locking it serializes exactly the
transactions that could race on that account's balance and nothing else.

## Seed and demo data

FR-006 requires an empty store be a usable starting point. `scripts/seed_demo_team.py`
already rebuilds demo and development state and stays the documented path — it moves to the
shared access path (R20), its `--db` argument becomes a DSN override, and its one
`INSERT OR IGNORE` and one positional row read are rewritten.

The demo identities in `app/models.py` (`DEMO_OWNER_STEAM_ID`, `DEMO_TEAM_ID`) are unchanged.
